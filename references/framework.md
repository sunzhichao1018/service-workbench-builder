# 可复用业务工作台框架

## 六个业务语义

框架围绕六种语义组织文件、页面与计算。它们是建模工具，不要求用户必须提供六份文件，也不要求所有场景启用全部模块。

| 语义 | 表达的事实 | 关键设计 |
|---|---|---|
| 业务对象 | 客户、门店、项目、设备、活动或其他被管理主体 | 稳定 ID 作为关联锚点；名称、负责人、分组和地区作为可变属性；同名不直接合并 |
| 任务/应履约 | 承诺完成什么、何时完成、由谁负责、按什么标准完成 | 任务与对象关联；计划数量、截止日期、周期和规则可选；没有业务承诺时不凭状态推算应交付量 |
| 执行与验收 | 实际发生的动作及被确认通过的结果 | 执行、提交、证据、验收分别表达；数量与单位保持一致；没有验收事实不把执行量自动视作验收量 |
| 收入与支出 | 实际或预估的业务流入、流出 | 发生日期、金额单位、币种、状态与关联对象可追溯；已发生、预估、待确认分开；缺少一侧不能宣称完整净收益 |
| 人工跟进 | 使用者在工作台补充的负责人、处理状态、备注或其他可编辑信息 | 与导入事实分开存储；明确显示操作覆盖的内容；新导入不静默抹掉人工跟进 |
| 审计与来源 | 内容来自哪个文件/批次，以及谁在何时改动了什么 | 保留来源摘要、源记录标识、导入结果与修改历史；本机操作者标识仅作记录，不当作企业身份认证 |

同一张用户表可以映射到多个语义，但生成时应避免将同一金额或同一事件重复统计。任务、执行和收支属于不同粒度；关联应明确一对一或一对多，并检查跨表连接是否放大记录数量。

## 从原工作台保留的设计

原工作台有价值的部分是业务闭环和信息边界：

- **事实→操作→汇总。** 保存用户导入的事实与来源，单独记录人工操作，从明确口径计算页面汇总。
- **首页→明细→对象。** 指标、进度和异常都能找到对应记录；下探时沿用相同对象、日期和状态条件。
- **计划→执行→验收。** 用户可以区分承诺、实际动作和被确认的交付结果。
- **导入→质量核对→可追溯更新。** 保留批次、字段映射、重复识别与错误原因，提供稳定更新方式。
- **未知值可见。** 缺失数据进入待补或待核对，不用零伪装完整性。
- **变更有记录。** 人工跟进保留修改历史；需要多人并发编辑时，另行实现版本校验。

这些设计用于新的空框架；Skill 不携带原业务数据库、数据行、附件、账号、连接凭据或历史导入结果。

## 移除的领域限定

业务对象不再固定为特定行业主体，服务项与任务类型不再使用固定清单。权益数量、周期锚点、费用单价、佣金规则、阶段顺序、超时门槛和验收条件均来自新用户的文件或明确说明。

不要把旧项目的默认规则当作新业务规则。例如项目任务可以按截止日期管理，销售机会可以按阶段管理，运营快照可以只展示当前分布；没有必要为这些场景自动引入周期权益、验收数量或财务模块。

## 未知值和统计完整性

区分以下情况：

| 状态 | 表达 | 展示和计算 |
|---|---|---|
| 已知为零 | 用户明确记录数量或金额为零 | 显示零，可以参与已定义口径的计算 |
| 未知/缺失 | 来源未提供或无法可靠解析 | 显示待补；计算中报告未覆盖数量，不静默按零计入 |
| 不适用 | 当前对象不属于该任务或指标范围 | 显示不适用，按明确规则排除分母 |
| 存在冲突 | 主键重复、关联歧义、状态或单位矛盾 | 进入质量问题，避免生成确定性的业务结论 |

对“总额”“完成率”“净收益”等名称，应检查数据是否支持这一完整含义。只有部分金额已知时，可以呈现“已知金额”和缺失条数；只有当前状态时，可以呈现状态分布；不能把这些结果包装成完整收入、全量履约或真实转化。

## 页面组合

按用途选择页面，不固定页面数量：

- 总览：核心指标、趋势或分布、数据覆盖和更新时间。
- 对象与台账：搜索、筛选、排序、明细与来源。
- 工作跟进：待处理事项、负责人、状态和备注。
- 质量与导入：文件识别、重复/拒绝情况、缺失与关联问题。
- 修改记录：查看实际记录下来的本机人工操作。

只有底座和实际配置已实现的交互才展示为可操作控件。若业务需要完整派单、复杂验收、原始附件存储或财务审批，应在实际实现并验证后增加，不能使用空按钮或浏览器内状态模拟已持久化能力。

## 运行范围与扩展

可运行底座使用 Python 标准库，读取 CSV、XLSX、JSON、JSONL，并将新用户的数据与人工跟进保存到本机 SQLite。新工作台应建立独立输出目录；分发 Skill 时只包含代码、规则说明、空白模板和必要合成测试材料，不包含运行后数据库或用户文件。

本底座面向本机单人使用。界面中的操作者、负责人或团队字段是业务数据，不构成团队鉴权、行级权限或云同步。

若用户需要多人共享、账户权限、定时任务、云端服务、源系统写回或外部通知，先界定使用者、部署环境与数据范围，再核验现有平台能力，设计独立接入方案并完成必要实现与验证。普通本机文件导入和生成空白工作台不需要因此增加额外批准步骤；对真实外部写入或覆盖操作，遵循该次任务已有授权和环境要求。
